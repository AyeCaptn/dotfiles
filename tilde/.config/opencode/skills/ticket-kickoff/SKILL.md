# Ticket kickoff

Build a shared understanding through a short conversation before implementation.

- Read the ticket, relevant code, and project instructions. Investigate what the
  code can answer; ask the user about intent and genuine choices.
- Discuss one meaningful question at a time. Give just enough context, a concrete
  idea, and your recommendation. Wait for the answer before asking the next.
- Keep your working approach internally. Don't present a plan, checklist, long
  explanation, or create planning files.
- Keep the exchange brief. Don't invent questions or speculative design work.
  When the direction is clear, briefly confirm your understanding and start coding.
- Reopen discussion only when new information materially changes the approach.

Skip this workflow for small, straightforward edits.
